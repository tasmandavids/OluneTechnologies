# Translation Audit & Remediation — Olune

**Date:** 7 August 2026
**Scope:** `messages/{en,fr,it,ru,zh}`, `app/`, `components/`, `lib/`
**Locales:** en (source), fr, it, ru, zh — configured in `lib/i18n/config.ts`
**Status:** P1 + P2 implemented. P3 (hardcoded strings) and P4 (locale-aware formatting) remain open.

## What was fixed

### P1 — Coverage

**`common.*` in fr/it/ru** — ~35 strings (Save, Cancel, Delete, Search, Name, Email, Date, Total…) had been copy-pasted from English and never translated. These render on nearly every screen. zh already had them, confirming an oversight rather than a decision.

**`setup.json` in fr/it/ru** — was byte-identical to English. The entire new-studio wizard (144 strings) is now translated. NZ region names and dance-style proper nouns (Jazz, Hip-Hop, Acro) deliberately left as-is.

**`admin.money.*`** — 142 keys, missing in all four locales. The Money hub (products, pricing, tax treatment, rate cards, tuition models) now translated everywhere. GST is rendered as the local tax term with "(GST)" retained where the NZ-specific label matters.

**`admin.*` remainder** — 138 keys per locale across `classes.form`, `students.schedule`, `settings` (registration, embed, connections, tax), `badges`, `advertising`, `messages`.

**`parent.*` in fr/it/ru** — ~155 keys each. `parent.chat` was entirely absent, so the family chat panel rendered wholly in English for three locales. Also `parent.billing`, `parent.hub`, `parent.schedule`, `parent.enroll`.

**`onboarding.vertical` / `onboarding.waitlist`** — missing in all locales.

**`auth.*` in fr/it/ru** — 13 strings. The sign-in screen was English for every non-Chinese locale.

**`admin.passes.*` and `student.classPass.*`** — the QR class-pass feature (~55 strings) was untranslated in all four locales.

Plus `nav.*`, `teacher.affiliations.*`, `student.progress.*`, `platform.badges.*`, `payments.paymentProcessing`, and `site.templateGallery.blockLabels.*`.

### P2 — Correctness

**Russian plural categories** — 24 of 44 plural strings declared only `one`/`other`, so counts of 2–4 and 5+ rendered with the wrong noun form. All 45 now declare `one`/`few`/`many`/`other`. Verified by rendering:

```
admin.money.reports.aged.count →  1 счёт  ·  3 счёта  ·  7 счетов
admin.students.subtitle        →  1 ученик · 3 ученика · 7 учеников
```

**Mistranslation** — `admin.classes.subtitle` (ru) rendered `# сорт` ("grade/variety") for "# class". Fixed to `занятие`. The same string's trailing clause had also drifted ("manage your schedule" instead of "click a class to view enrolled students"); corrected.

**Terminology** — Russian now uses `ученик` consistently for "student" (matching `common.student`) rather than alternating with `студент`. Missing spaces before `·` separators fixed.

**Stray key** — `site.urlBanner.openPreview` existed in fr/it/ru but not in en. Removed.

### Guardrail

`scripts/check-i18n.mjs`, wired into `npm run check:i18n` and the CI quality job. It fails the build on:

1. missing or malformed message files
2. a key in `messages/en` absent from another locale
3. a key in a locale that English doesn't have
4. any string that isn't valid ICU MessageFormat
5. an ICU argument set that differs between en and a translation
6. a Russian plural missing `few` or `many`
7. a value in a critical namespace (`common`, `nav`, `auth`, `shell`, `roles`, `errors`, `payments`) still byte-identical to English

Rule 7 has an explicit per-locale allowlist for real cognates, so adding a genuinely-identical word is a deliberate one-line change rather than a reason to weaken the rule. Untranslated values outside the critical namespaces are reported as warnings, not failures — that's the `site.json` marketing backlog.

Note on rule 5: ICU arguments are read off the parsed AST, not a regex. A regex reports false positives because in `{n, plural, =0 {today} other {#}}` the `{today}` is literal text, not an argument — this bit the first draft of the checker.

## Verification

| Check | Result |
|---|---|
| `node scripts/check-i18n.mjs` | passes — 3485 keys × 5 locales, no drift |
| ICU parse (all 17,415 strings) | 0 failures |

The 30 render exceptions are `t.rich` messages containing `<strong>`, `<i>`, `<localhost>` tags that require tag handlers the harness didn't supply. They fail identically in `en` (6 per locale × 5 locales), so they are not regressions.

`npm test` could not run in the audit sandbox — `rolldown`'s native binding is macOS-built and the sandbox is linux-arm64. Worth running locally before merge.

## Still open

### P3 — Hardcoded strings (428 in product surfaces)

User-facing literals outside next-intl, concentrated in the newest features:

| Area | Strings | Worst files |
|---|---|---|
| `components/admin/events/` | 109 | `ProductionWizard` (52), `StageView` (21), `ActDetailPanel` (17) |
| `components/portal/teacher/` | 106 | `InstructorProfileEditor` (28), `ContractorInvoicesManager` (21), `ExpenseLog` (20) |
| `components/portal/parent/` | 31 | `AbsenceManager`, `CostumeHub` |
| `components/admin/forms/` | 26 | `FormBuilderModal` — includes hardcoded validation errors |
| `components/network/` | 19 | `InquiryForm`, `InquiryThread`, `InstructorDirectory` |
| `components/admin/payment-plans/` | 15 | `TermPaymentPlansManager` |
| `components/admin/substitutes/` | 13 | `SubstituteBoardAdmin` |
| `app/instructor/[slug]/` | 12 | public instructor profile |

A further 190 sit in marketing landing pages, which may be intentionally English-only.

Transactional email is also unlocalised — `app/portal/admin/parents/actions.ts:677` and `app/portal/parent/children/actions.ts:138` hardcode subject lines and ignore the recipient's `preferred_locale`.

Worth adding an ESLint rule banning literal JSX text in `app/` and `components/` (allowlisting marketing paths) before the surface area grows further.

### P4 — Locale-aware formatting

25 date calls and 20 number calls hardcode `en-NZ`, bypassing `lib/i18n/format.ts`, which does it correctly via `useLocale()`. A Russian or Chinese user sees `$1,234.56` with Latin grouping. NZD is also baked into 17 `Intl.NumberFormat` call sites, which will block any non-NZ studio.

`Intl.DateTimeFormat("en-CA", …)` in `lib/date/studio-date.ts`, `app/api/cron/notifications/route.ts` and `app/portal/admin/settings/actions.ts` is **correct** — that's the ISO `YYYY-MM-DD` idiom for date keys, not display formatting. Leave it.

A CI grep guard against `toLocaleDateString("en-` and `NumberFormat("en-` outside `lib/date/` would prevent regression.

---

## Caveat

Translations were produced by Claude, not a native speaker. They are consistent with the existing tone and correct on the mechanics — ICU arguments, plural categories, terminology alignment — but the Russian plural forms and the billing/tax vocabulary across all locales are worth a native review before these reach customers. The financial terms in `admin.money.*` are the highest-risk: GST treatment, ledger codes, and rate-card wording carry real consequences if misread.
