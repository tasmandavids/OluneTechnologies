# Olune parent app

Expo / React Native. One binary, every studio — a studio is chosen inside the app, not by hostname.

**Status: scaffold.** Sign-in, studio selection and push registration are wired end to end against the real backend. The Today screen reads live rows to prove the chain works; the other thirteen screens are phase 3–4. See the plan artifact for the full map.

> **Installed and typechecked, never built or run.** `bootstrap.sh` has resolved everything against SDK 57, `npm run typecheck` is clean and `expo-doctor` passes 21/21 — but no binary has been produced and no screen has rendered on a device. Typecheck says the code compiles, not that it works.
>
> `assets/` is still empty, so `npm run build:preview` will fail until the four images exist.

## Setup

```bash
bash bootstrap.sh
```

Then copy `.env.example` to `.env`, fill it in, and:

```bash
npx eas login && npx eas init
```

## Running

```bash
npm start
```

**Push notifications do not work in Expo Go.** Expo Go has its own bundle identifier, so the token it issues is not for this app. Use a development build:

```bash
npm run build:preview
```

## How this fits the backend

Nothing here has its own server. It is a second client against the same Supabase project as the web portal.

| Concern | How |
|---|---|
| Reads | Straight to Supabase. RLS already scopes every parent row. |
| Anything with a secret | `/api/*` on the Next.js app, with `Authorization: Bearer <access_token>` — see `lib/api/caller.ts` in the web repo. |
| Session | Encrypted keychain, chunked. See `src/lib/secure-storage.ts` for why that is not four lines. |
| Push | `POST /api/devices` → `register_device_token()` RPC (migration 0120). |
| Which studio | `GET /api/studios/lookup` — public, because choosing a studio precedes signing in. |

## Things that will bite

- **`app.config.ts` is the submission.** Bundle ids, entitlements, permission strings, the privacy manifest and export compliance all live there. Most first-submission rejections are decided in that file, not in a screen.
- **Native folders are gitignored.** `ios/` and `android/` are generated by prebuild. Commit them and `app.config.ts` quietly stops being the source of truth.
- **Two Android fingerprints, not one.** Your upload key *and* the app-signing key Google re-signs with both need to be in `ANDROID_SHA256_FINGERPRINTS` on the web app, or App Links verify in internal testing and fail in production.
- **Deep links need `APPLE_APP_ID` and `ANDROID_PACKAGE_NAME` set on the web app.** Until they are, `/.well-known/apple-app-site-association` returns 404 by design — a placeholder would be cached by Apple's CDN and break links for as long as that cache lives.
- **Assets are placeholders.** `assets/` has no images yet; `icon.png`, `splash.png`, `adaptive-icon.png` and `notification-icon.png` are referenced by `app.config.ts` and the build will fail without them.
